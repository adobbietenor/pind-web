## Configured by hand — none of this is visible from the repo

**This is the section a fresh session would otherwise rediscover or break.** Every
value here was set in a dashboard, and several of them must match a number in the code.

### Supabase Auth (pind-staging)

| Setting | Value | Must match |
|---|---|---|
| Site URL | `https://pind.social` | |
| Redirect URLs | `https://pind.social/**` · `pind-staging://**` · `http://localhost:8081/**` · `pind://**` | the app's `scheme` in `app/app.config.ts` |
| Anonymous sign-ins | on | |
| **Email OTP length** | **6** | `EMAIL_CODE_LENGTH` in `packages/shared/src/constants.ts` — they disagreed once (8 vs 6) and a valid code could not be entered |
| **Custom SMTP** | Resend, `smtp.resend.com`, sender **auth@pind.social**, its **own** Resend key named `supabase-auth` | Required, not optional: Supabase will not let templates be edited without it |
| **Templates carrying `{{ .Token }}`**, subject "Your Pin'd code" | **Confirm signup**, **Magic Link**, **Change Email Address** | A new address gets *Confirm signup*, not Magic Link — that is the one that hid the link-not-code bug |

### Google

- OAuth client in the Google Cloud project **PIND**.
- Authorised redirect URI, character for character:
  `https://mxuajvlrkggrqpntekqt.supabase.co/auth/v1/callback`
- **Consent screen named "Pin'd"**, in **Testing**, with every Google account Alex might
  tap added as a test user. Any other account gets "Access blocked".
- Enabled in Supabase with that client's ID and secret.

### Apple

- **Sign in with Apple** enabled on App ID `social.pind.app.staging`.
- **Services ID `social.pind.web`**, domains `pind.social` and
  `mxuajvlrkggrqpntekqt.supabase.co`, return URL the Supabase callback above.
  **Its primary App ID is the staging one**, because `social.pind.app` does not exist
  yet — re-pointing it is in M4.3's scope and acceptance.
- A **Sign in with Apple key**; the `.p8` is stored outside the repo. Apple lets it be
  downloaded once.
- Supabase's "Secret Key" is a **JWT minted from the `.p8`**, not the `.p8` itself:
  `node scripts/apple-client-secret.ts --key <path> --kid <Key ID>`.
- **It expires 2027-03-23** — recorded as `APPLE_SECRET_EXPIRES` in `wrangler.jsonc`.
  The admin shows it and the 09:00 cron alerts from six weeks out. **When it lapses,
  web Apple sign-in breaks and native keeps working**, so the half that works hides the
  half that stopped. Updating the date is half of rotating the secret.

### Supabase Vault and the Worker

- Vault: `photo_check_url` = `https://pind.social/hooks/photo-check`, and
  `photo_check_secret`. **The stored secret has whitespace round it**; both sides trim
  now, so it is harmless, and the admin says it is there.
- Worker secret **`PHOTO_WEBHOOK_SECRET`** — the same value. `/admin/config` compares
  the two by fingerprint and says whether they match.

### EAS

- The `development` environment carries the four public keys (Supabase URL and
  publishable key, PostHog, Sentry). `EXPO_PUBLIC_SITE_URL` is not set and does not
  need to be — it defaults to `https://pind.social`.

### Resend / DNS

- Domain `pind.social`. SPF on the root is Cloudflare Email Routing's and does **not**
  authorise Resend — fine while Resend sends from `send.pind.social`. DKIM present and
  aligned. **DMARC is `p=none` with no `rua`**, which is why Outlook junked the first
  code.
